## 一、双语言逐字节一致（` ```calc ` / ` ```sim ` 的头号杀手）

本技能要求 calc/sim 给出 **Python 与 R 两段**，且**两段的预期输出必须逐字节相同**。
这不是洁癖 —— 逐行 diff 是**唯一能机械发现「某一侧算错了」的手段**，因为人眼对两段相似输出的细微差异不敏感。

### 1.1 R 的 `1:0` 等于 `c(1,0)`，**不是空**

```r
for (j in 1:0) f <- f * j     # 会执行两次：j=1、j=0 ⟹ 结果被乘成 0
```

**实测后果**：`factorial(0)` 返回 `0` ⟹ 除零 ⟹ `R_k = -Inf`。
**Python 的 `range(1, 1)` 是空**，所以两边**语义不同而都不报错**。

```python
def fact(m):
    if m < 1:
        return 1.0           # ← 护栏，两边都写
    f = 1.0
    for j in range(1, m + 1):
        f = f * j
    return f
```

```r
fact <- \(m) {
  if (m < 1) return(1.0)      # ← 同一道护栏
  f <- 1.0
  for (j in seq_len(m)) f <- f * j
  f
}
```

**规矩**：
- R 里**凡是循环上界可能为 0 的，一律用 `seq_len()`**，不用 `1:n`；
- Python 侧**同时**加显式护栏 —— **不是为了防 Python 出错，是为了让两边算法在纸面上就长得一样**。

### 1.2 R 顶层裸 `sprintf()` / `print()` 会**自动打印返回值**

```r
sprintf("%.10f", pi)          # 控制台多出一行：[1] "3.1415926536"
cat(sprintf("%.10f", pi), "\n", sep = "")   # ← 正确写法
```

**实测后果**：预期输出里多出 `[1] "..."` ⟹ 逐字节 diff **必挂**。

### 1.3 R 的整数除法

```r
v <- m / d        # m、d 都是整数时是整除！
v <- m * 1.0 / d  # ← 强制浮点
```

**实测后果**：`140 / 99` 变成 `1` ⟹ 平方判定全错。

### 1.4 `sprintf("%-12s")` 在 R 按**字节**补位、在 Python 按**字符**补位

**这是本清单里最隐蔽的一条**，因为它只在标签里含中文时才发作：

```
R : "x/x+1 跳跃"     ← 3 个中文字符 = 9 字节，补位按 9 算
PY: "x/x+1 跳跃"     ← 补位按 3 个字符算
```

**实测后果**：两边空格数不同 ⟹ 逐字节 diff 挂 1 行。

**规矩**：**`sprintf` 里带宽度限定符（`%-12s`、`%8.3f` 之类）的字段，标签一律用纯 ASCII**。
中文只放在**末尾无宽度限定**的字段里（那里不补位，两边自然一致）。

### 1.5 R 的 `sum(expr for j in seq)` 生成器在某些写法下解析失败

```r
T <- sum(x^j/prod(1:j) for j in 0:(k))     # ← unexpected 'for'
```

**规矩**：**两侧都用显式循环**。教学 calc 本来就要看得懂，显式循环比生成器更合适。

## 二、验证脚本自身的陷阱（**这一节最容易发出假合格信号**）

### 2.1 ⭐⭐ 对比脚本硬编码输入路径 ⟹ **比的是旧文件，还报「一致」**

**实测后果（本会话发生）**：一个临时 diff 脚本里写死了上一张卡的输出文件名，
换卡后**照常输出「逐字节一致：是」** —— 而它比的是**几十行前的旧数据**。

**规矩（铁律）**：
- **所有对比脚本必须参数化**（`sys.argv` 收路径），**禁止**在脚本里写死具体文件名；
- 对比前**先确认两个文件的修改时间**与目标一致；
- 报告里**必须写出「比的是哪两个文件」**，不能只写「一致 / 不一致」。

### 2.2 ⭐⭐ 验证脚本里的**硬编码叙述**会与它自己的输出矛盾

**实测后果（本会话发生）**：脚本末尾写死一句总结「$140/99$ 是上界」，
而它自己上面算出来 $140/99$ 的平方 $=1.999796<2$ —— **表是对的，叙述是错的**。

**规矩**：
- **卡片里只准引用脚本的「输出表格」，不准引用脚本的「文字叙述」**；
- 写完叙述后**回头对一遍表**，看每一句是否被表支持；
- 更好的做法：**让脚本直接输出你要写进卡片的那句话**（`print("⟹ 上确界 = ...")`），
  这样叙述与数字**由同一份代码生成**，不可能矛盾。

### 2.3 临时脚本名撞标准库

```
C:\...\Temp\struct.py   ← 会打断 numpy 的 import 链（pickle → struct）
ImportError: cannot import name 'pack' from 'struct'
```

**规矩**：临时脚本**不要用标准库同名的词**（`struct`、`types`、`code`、`json`、`random`、`select`、`math`、`copy`、`time`、`io`、`email`、`profile`、`test`、`token`）。
**养成习惯**：临时脚本一律带前缀（`t_py.py`、`dcmp.py`、`chk3.py`）。

### 2.4 ⭐⭐ `--dry-run` 只证明「两侧互相一致」，**证明不了「卡里的预期输出没过期」**

**这是最隐蔽的一类假合格信号**：`verify_calc.py --dry-run` 把 Python 段与 R 段各跑一次、
逐字节比对 —— 全部通过。但**卡里那段已写死的「预期输出」注释，从头到尾没被碰过**。
若某天改了 calc 代码（改精度、改循环、换 Python/R 版本），
`--dry-run` 照样报「✓ 逐字节一致」（因为两侧的新输出仍彼此一致），
而卡面上印的仍是**旧数字** —— 读者照着卡片核对，会对不上。

**规矩**：把「回放」做成一道显式的门禁 ——
```bash
python3 scripts/verify_calc.py "概念卡/概念名-概念卡.md" --replay
```
它把两段已填的预期输出**打回占位符 → 用实跑重建 → 与原卡逐字节对账**。
**改了 calc 代码、或换了 Python/R 版本之后必须补跑**。

**实现上的一个坑**：打回占位符时，段的范围是「`# 预期输出:` 之后**连续**的 `# ` 开头行」，
终止条件**必须显式排除** `# R` 与 `# PYTHON` —— 它们本身也以 `# ` 开头。
漏掉这一条会把整个 R 段一起吞进占位符，表现为「R 实跑 → 0 行」（**不报错**）。

## 三、质检脚本的已知局限（**别把它当地面真值**）

### 3.1 `check_card.py` 的公式闭合检测按**单行**计数

```markdown
$$\begin{aligned}
a &= b\\
c &= d
\end{aligned}$$
```

`$$` 分处两行 ⟹ 每行都是奇数个 ⟹ **误报「疑似未闭合」**。

**规矩**：**行间对齐环境（`aligned`/`cases`/`array`/`matrix`）必须写在同一行**。
`\begin{aligned} a &= b & c &= d \end{aligned}` 这样写，既不误报也能正常渲染。

### 3.2 判「`$` 未闭合」时**必须跳过代码块**

代码里 `qr(A)$rank`、`df$x` 是**合法语法**。统计 `$` 个数时若不剔除围栏块，
R/Python 代码块会制造大批假报警。

### 3.3 `card_final.py` 的「裸竖线」计数**不可信**

它把表格的**列分隔符 `|`** 也算成裸竖线 ⟹ 数字虚高。
**地面真值只有一个**：**渲染后的 HTML**。
- 表格列数一致性 ⟹ 看 HTML 里 `<td>` 的实际列数；
- 公式回落率 ⟹ 数 HTML 里 `class="math-src"` 的个数。

### 3.4 `lint_skill.py` 的难度体检认「层次声明」豁免

工具在某张卡的 F6 平移栏出现 ⟹ 报「承重行」。
**修法不是删掉那个词**（它常常是有价值的横向连接），而是**在卡首的〔层次声明〕里点名它**，
并在同一句里写明「只点名字、一个定义都不给」。

**顺带一条**：若某卡是链条的**第 0 个 / 第 1 个概念**，它**整条下游链**都算「更后面的工具」，
**一次性在层次声明里列全**比逐个补省事得多。

## 四、卡片改名 / 拆分 / 归档后的引用同步

**这是最容易留下「指向不存在的卡」的地方。** 一张卡被改名或拆成两张，
**其他卡里对它的引用会全部失效，而且脚本查不出来**（因为文本仍存在、只是名字不对）。

**固定程序**：
1. 新卡**先全部通过**质检（`lint --self` / `check_card --run` / `md2card` / 难度体检 / 成品体检）；
2. 旧卡**归档**（移动到**卡片目录之外**的子文件夹 —— 质检脚本只 `glob("*.md")`，不会扫到；
   **不要硬删**）；
3. 全目录扫旧卡名，逐条判断**该指向新卡的哪一张**，再替换；
4. **概念序号重排**（插入新卡会让后面所有卡的「第 N 个概念」失效）；
5. **重新生成被改动过的那些卡的 HTML** —— 只改 md 不重生成，HTML 会静默停留在旧内容；
6. 最后**再跑一次全目录体检**，并**确认 md 与 html 数量一致**。

**替换时用显式 (旧串, 新串) 对 + 断言命中数**，不要用正则模糊替换 ——
并让脚本最后报告「仍提到旧卡名的行」，逐行人工确认是**教材章节名**（合法）还是**真引用**（要改）。

## 五、Windows / PowerShell 环境

| 坑 | 表现 | 修法 |
|---|---|---|
| `>` 重定向 | 写出 **UTF-16**，后续按 UTF-8 读全是乱码 | `| Out-File -Encoding utf8` |
| 控制台读中文 | 常见乱码（`瑙﹀垝闄愭…`） | **不要从控制台读中文**：让脚本直接写 UTF-8 文件，再读那个文件 |
| `NativeCommandError` | R/Python 明明成功，PowerShell 仍报错 | **stderr 假象**，不是真错误；看退出码与实际输出 |
| `1:0` | 见 §1.1 | `seq_len()` |
| **`write_text` 漏 `newline="\n"`** | 产物变 **CRLF**；跨平台不可复现；每次重渲都出现「只有换行不同」的伪改动 | 见下 §5.1 |
| PowerShell 上一条命令的输出 | 可能漏进**下一条命令的参数**里（尤其带 `\|` 的管道与 here-string） | 用**纯 Python 驱动**跑批量测试，别在 shell 里串 |

### 5.1 ⭐ `write_text(..., encoding="utf-8")` 在 Windows 上会写出 CRLF

`Path.write_text` / `open(..., "w")` **不给 `newline` 参数**时，Python 用平台默认的换行翻译：
**Windows 上把 `\n` 翻成 `\r\n`**，macOS / Linux 上不动。后果：

- 同一份 md 在 Windows 与 Linux 上生成**不同字节**的 html ⟹ 「可复现」是假的；
- 本技能 `.gitattributes` 声明 `* text=auto eol=lf`（仓库内统一 LF），于是
  **每次重渲都让工作区出现一批「只有换行不同」的伪改动**，污染 diff。

**规矩**：**所有产出文本文件的 `write_text` / `open(...,"w")` 一律显式给 `newline="\n"`**。

**怎么发现的（值得记住的推理）**：核对 4 张旧样例卡的 html 是否过期，发现与当前渲染器
的大小差是 **+1603 / +1767 / +1794 / +1850 字节** —— 我一眼觉得这几个数眼熟：
它们**恰好等于各自的行数**。于是判断「内容一致、只差换行符」，顺着查到了写文件那两行。
⟹ **尺寸差 ≈ 行数 时，先怀疑换行符**；尺寸差是别的数，才怀疑内容。

**防回归**：`scripts/lint_skill.py --self` 的第 [5] 项会全仓扫 CRLF，命中即 FAIL。

## 六、写 calc 块的固定流程（**照抄这个顺序，不要自由发挥**）

1. **先用 `scripts/verify_calc.py --dry-run <card.md>`** 抽出 calc 块的 Python 与 R 两段，分别实跑；
2. **两侧不一致就停下**，按 §1 逐条排查（R 的 `1:0`、整除、`sprintf` 自动打印、宽度补位）；
3. 一致后跑 `scripts/verify_calc.py <card.md>` —— 它会**程序化把实跑输出填进两个 `<<<EXPECTED>>>` 占位符**，
   并在写回前**断言必需章节齐全、围栏成对、`〔教材口径〕` ≤ 6、占位符已全部替换**；
4. 再跑 `scripts/check_card.py <card.md> --run`；
5. **最后人工复算一遍表**（§2.2）。

> **为什么第 3 步要「程序化填充」**：手抄 `%+16.6f` 这类格式串时，
> **空格数、指数位数、正负号**极易出错，而**逐字节 diff 会因此挂行**，
> 于是你开始怀疑 diff 脚本 —— 正是 §2.1 那种假合格信号的入口。
> **让代码生成数字，就永远抄不错。**

> **第 3 步之后、交付之前补一条**：`scripts/verify_calc.py <card.md> --replay`。
> `--dry-run` 只比两侧新输出，`--replay` 才验证**卡面上那段写死的数字没错**（§2.4）。

## 七、画廊 / 样例卡（`examples/`）的元数据格式

`scripts/make_gallery.py` **从卡片正文抽元数据**（不另维护清单），
所以 `所属:` 行的格式一旦漂移，画廊就会**静默串台**。实测踩过三种。

### 7.1 `所属:` 行的值必须能被切成「学科 · 位置 | 教材」

规范写法（**学科在 `·` 前**）：
```
> 📌 所属：数学分析 · 第 0 个概念 | 教材：以你教材「实数集与确界原理」一节为准
```
需要「认知动作」徽章时，用 `｜` 追加（**注意是全角竖线，且要在 `| 教材` 之前**）：
```
> 📌 所属：数学分析 · 第 0 个概念  ｜ 认知动作：逼近（连续）| 教材：…
```

**串台后果**（都真发生过）：
| 写法 | 画廊显示 | 原因 |
|---|---|---|
| `所属：数学分析 · **第 0 个概念（地基…）**` | 课程名 = `第 0 个概念`（位置被当成学科） | 抽取时取了 `·` 的**后半段** |
| `所属：概率论 · 随机变量（测度论的可测函数）| 教材：…` | 课程名拖着一个括号尾巴 | 没截断到第一个 `（` |
| `认知动作：逼近（连续）| 教材：…` | 动作变成 `逼近（连续）| 教材：…` | 动作正则没在 `|` 处停下，把「教材…」也吞了 |

**规矩（抽取的三条顺序，不能颠倒）**：① 先按 `认知动作：` 把类别单独切出来；
② 余下部分截到第一个 `｜`/`|`；③ 课程名取 `·` **前半段**；④ 括号注释截断、`**` 清掉。

### 7.2 老卡与新卡的 `认知动作` 是**两种东西**，别混

| 卡态 | 写法 | 含义 | 画廊用法 |
|---|---|---|---|
| 老卡（F5 里） | `**认知动作：逼近（随机）** —— …` | **认知类别**（徽章用） | 直接取 |
| 新卡（F5 里） | `**认知动作 = 拖 $\delta$，盯住…**` | **怎么拖**（交互说明） | **不取**（等号形式要排除） |

**规矩**：类别只在 `所属` 行或 `认知动作：`（冒号）形式里取；
`认知动作 =`（等号）是交互动作描述，**不要**当成类别喂给画廊。

### 7.3 改完 `make_gallery.py` 必须重跑并**核对卡片顺序**

画廊成员来自**目录扫描**、顺序来自脚本里的 `ORDER`（列表外的按文件名排序追加）。
新卡若忘了进 `ORDER`，会散落在末尾、打乱教学脉络。
重建后**肉眼过一遍顺序**：数学分析链应按 确界→极限→连续→导数→微分→中值→洛必达→泰勒。

```bash
python3 scripts/make_gallery.py     # 重建 examples/index.html
```
