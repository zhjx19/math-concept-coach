# 图形化演示指南（Visual Facet）

> 图形化的目的**不是装饰**，而是把 F3 的严格表述「翻译」成可以动手做的实验。
> **纪律：没有操作引导语的图，等于没有图。** 每张图都必须配一句「拖什么、看什么、先预测什么」。

## 一、三条路径与优先级

用户要求：**网页里直接有动态交互图形**（不依赖 GeoGebra），同时**顺带给出 GeoGebra 指令**供学生自己用软件复现。

| 优先级 | 路径 | 用什么 | 产出 | 何时用 |
|---|---|---|---|---|
| **①（默认·主力）** | **自绘交互组件** | ` ```interactive ` 块 + `assets/card-widgets.js` | 网页内**可拖动的 Canvas 图形**，单文件离线 | **几乎所有需要「看变化」的概念** |
| **②（总是附带）** | **GeoGebra 指令** | ` ```geogebra ` 块 | 一段可复制粘贴的 GeoGebra 命令 | **每次做 ① 时都同时给**，让学生能自己动手 |
| **③（辅助）** | 静态结构图 | 内联 SVG | 示意图 / 关系图 | 纯结构概念（如「向量组张成」的示意、楼层关系） |

```
这个概念需要「拖动参数看变化」吗？
├─ 是 → ① 自绘交互组件（interactive）
│        └─ 同时补一段 ② GeoGebra 指令（geogebra）
└─ 否 → ③ 静态 SVG，或干脆用表格讲清楚
```

> **不再需要探测 GeoGebra 服务**：路径 ① 完全自绘、零依赖，直接可用。GeoGebra 只以**文本指令**形式出现，学生在自己电脑上打开 GeoGebra 输入即可——不依赖本机 MCP。

### 先回答「设计三问」，再动手做图

做 F5 前先回答三个问题，否则做出来的只是会动的插图，不是实验。
（三问借鉴自 [math-viz-kit](https://github.com/edu-ai-builders/math-viz-kit) 的设计理念。）

| 问 | 它在逼你想清楚什么 | 不合格的答案 |
|---|---|---|
| **① 为什么要可视化？** | 这个知识点是不是「静态图讲不清楚、动态一秒懂」 | 「加个图更清楚」（那就不必画） |
| **② 让大脑做什么？** | 这张图只承载**一个**认知动作 | 「又能看曲线又能看斜率还能看面积」（一个都不深） |
| **③ 反馈说什么？** | 学生拖完之后，**该看出哪条规律** | 「显示 S₈=0.27344」（只是数字，不是规律） |

### 认知动作 → 组件 → 该揭示的规律

**第 ② 问是核心：先定认知动作，再选组件。** 不要从"我有哪些组件"出发。

| 认知动作 | 它在问什么 | 组件 | 典型概念 | 反馈必须揭示的规律（❌ 只报数值） |
|---|---|---|---|---|
| **逼近（离散）** | 一直靠近的终点是什么？ | `seq` | 数列极限 ε–N | ✅ ε 每缩小 10 倍，N 约增大 10 倍（1/n 慢在哪） |
| **逼近（连续）** | 输入够近，输出就近吗？ | `plot` | 极限 / 连续 / **一致连续** | ✅ 同一个 δ 在陡峭处失效——这正是"一致"难在哪 |
| **变换** | 空间被怎么动了？ | `matrix2` | 线性变换 / 行列式 / 秩 | ✅ det 变号=翻转，det=0=压扁降维（秩<2） |
| **累积** | 无穷多个无穷小加起来是多少？ | `riemann` | 定积分 | ✅ n 翻倍误差约减半；左右矩形一个偏大一个偏小 |
| **分解/张成** | 这几个向量能拼出什么？ | `vectors2` | 线性相关 / 张成空间 | ✅ 共线 ⟺ det=0 ⟺ 张成空间塌成直线 |
| **比较** | 两个容易混的概念差在哪一条？ | `plot`（对照） | 连续 vs 一致连续 | ✅ 差别不在"每点连续"，而在"δ 能否共用" |

> **关于第 ③ 问**：`hint` 里必须写清"拖完之后该看出什么规律"，
> 不能只写"拖着看看"。数值是学生自己能读的，**规律才是你要给的**。
> - ❌ `hint`：拖动 n 观察 S_n 的变化
> - ✅ `hint`：把 n 从 4 拖到 8 再到 16——误差是不是每回差不多减半？这就是"收敛速度"

### 概念 → 组件 速查（定完认知动作后查这里）

| 概念 | 认知动作 | 组件 | 拖动什么、看什么 |
|---|---|---|---|
| ε–δ 极限、连续 | 逼近（连续） | `plot` | 拖 `d`（δ）、`x0`：曲线是否留在 ε 带里 |
| **一致连续** | 比较 | `plot` | 固定 δ 只移动 `x0`：哪些位置会冲出 ε 带 |
| 导数（割线→切线） | 逼近（连续） | `plot` | 拖 `h → 0`：割线趋向哪条线 |
| 中值定理 | 比较 | `plot` | 拖区间端点：平行弦何时与曲线相切 |
| 数列极限 ε–N | 逼近（离散） | `seq` | 拖 `eps`：N 怎么变 |
| 定积分 / 黎曼和 | 累积 | `riemann` | 拖 `n`：S_n 逼近精确值 |
| 线性变换 / 行列式 / 秩 | 变换 | `matrix2` | 拖 `a b c d`：单位正方形何时压扁成线段 |
| 线性相关 / 张成空间 | 分解/张成 | `vectors2` | 拖向量：何时共线、张成空间塌成直线 |

> 完整参数规范见 **`references/widget-spec.md`**——写组件前必读。

## 二、自绘交互组件（路径 ①，主力）

在概念卡里写一个 ` ```interactive ` 块，内容是 JSON：

```interactive
{"type": "plot", "expr": "sin(1/x)", "xrange": [0.02, 1], "yrange": [-1.35, 1.35],
 "sliders": [{"name": "x0", "label": "x₀", "min": 0.03, "max": 0.9, "step": 0.01, "value": 0.6},
             {"name": "d", "label": "δ", "min": 0.005, "max": 0.25, "step": 0.005, "value": 0.06}],
 "overlays": [{"kind": "vband", "x": "x0", "half": "d"}],
 "points": [{"x": "x0", "y": "f(x0)", "label": "A"}, {"x": "x0+d", "y": "f(x0+d)", "label": "B"}],
 "hint": "固定 δ，移动 x₀：哪个位置 A、B 的高度差会冲破 ε？"}
```

`md2card.py` 会把它渲染成可拖动的 Canvas 图形。**六条硬要求**：

1. **必须是 JSON**（严格双引号），顶格写在 ` ```interactive ` 块里。
2. **乘法写全**：`2*x`，不能写 `2x`；幂用 `^`。
3. **变量名必须来自 `sliders`**（`plot` 的自变量是 `x`，`seq` 是 `n`）。
4. 主函数在叠加层/标记点里用 `f(...)` 调用，如 `f(x0)`、`f(x0+d)`。
5. `xrange` / `yrange` 要**保证把滑块推到端点时曲线仍在画面内**。
6. **必须配 `hint`**——一句操作引导语。

## 三、GeoGebra 指令（路径 ②，总是附带）

每次做了交互组件后，**再给一段 GeoGebra 指令**，让学生能在自己的 GeoGebra 里复现同一件事：

````
```geogebra
f(x) = sin(1/x)
SetColor(f, 0.18, 0.44, 0.70)
d = Slider(0.005, 0.25, 0.005)
x_0 = Slider(0.03, 0.9, 0.01)
A = (x_0, f(x_0))
B = (x_0 + d, f(x_0 + d))
Segment(A, B)
```
````

渲染后会带一个 **「复制指令」按钮**。写法规则：

- **一行一条命令**，学生逐行粘贴到输入栏。
- 颜色用 `SetColor(obj, r, g, b)`（0–1 的 RGB）——最稳。
- 滑动条用 `Slider(min, max, increment)`。
- 装饰性命令（颜色/线宽）**放最后**，并提示「报错可整行删掉」。
- 指令与 ① 里的组件**讲同一件事**，学生能对照。
- **不确定版本兼容性的命令宁可不写**。核心三件套（`f(x)=…`、`Slider(…)`、取点连线）几乎一定可用。

## 四、什么时候「不画」

- 概念本身是纯结构的（「数域」「欧氏空间」的公理化体系）→ 用**表格 + 结构图**（路径 ③ 的 SVG），别硬画曲线。
- 图会误导（把「一致连续」画成「图像一直在带子里」却不说明 δ 必须同一个）→ 宁可不画，或在图上明确标注。
- **没有把握画对** → 不画。宁可少一张图，不交一张错的图。

- [ ] 跑过 `scripts/check_card.py` 吗？改过组件库的话跑过 `scripts/smoke_test_widgets.mjs` 吗？

## 六、技术要点（维护组件库时看）

- 组件库：`assets/card-widgets.js`（零依赖 IIFE，由 `md2card.py` 注入卡片）。
- 参数传递：`<div class="wb-widget" data-wb="类型" data-spec="base64(JSON)">` —— **用 base64 是为了让参数不受 Markdown 解析影响**（pandoc 会解析 `<div>` 容器内的 Markdown）。
- 知识图谱 SVG：由 `scripts/knowledge_map.py` 生成，**逐元素换行**（挤成一行会被 pandoc 在空格处折断）。
- 回归测试：`node scripts/smoke_test_widgets.mjs` —— 用 DOM 桩把 5 类组件各渲染一遍，校验数值与绘图范围。
